H.265 CCTV Motion Leak — Điều tra giấu tin bằng motion vector
Mức độ: Trung bình Network Forensics Video Steganography

1. Giới thiệu Lab

Thông tin Chi tiết
Tên Lab h265-cctv-motion-leak
Mức độ Trung bình
Công cụ sử dụng curl, tcpdump, ffprobe, strings, grep, python3, nano

Mục tiêu học tập

Bài lab giúp sinh viên thực hành điều tra một video camera H.265 bị nghi dùng làm kênh rò rỉ dữ liệu. Sinh viên cần tải chứng cứ từ máy chủ nội bộ, bắt gói quá trình tải file, kiểm tra video, chứng minh không có SEI dễ thấy, phân tích motion vector và khôi phục thông điệp ẩn.

Kỹ năng đạt được

  • Tải chứng cứ qua HTTP bằng curl.
  • Bắt gói HTTP bằng tcpdump.
  • Kiểm tra video H.265 bằng ffprobe.
  • Phân tích NAL và kiểm tra dấu vết SEI.
  • Hiểu cách giấu bit bằng tính chẵn/lẻ của mv_x.
  • Sửa code Python nhỏ để trích xuất thông điệp.
  • Đọc log máy chủ và viết kết luận điều tra.

2. Kịch bản

Tình huống: Một công ty logistics bị lộ lịch vận chuyển hàng giá trị cao. SOC phát hiện trước thời điểm rò rỉ có một file camera H.265 được tải ra khỏi máy chủ nội bộ.

Vấn đề: Video nhìn bình thường, không có chuỗi ASCII rõ ràng và không có dấu hiệu SEI dễ thấy. Dữ liệu ẩn được giấu trong LSB của các mẫu motion vector mv_x.

3. Kiến thức bổ trợ

Motion vector trong video nén

Motion vector mô tả hướng và độ dịch chuyển của vùng ảnh giữa các frame. Trong bài lab này, thông điệp được mã hóa bằng tính chẵn/lẻ của thành phần mv_x.

Quy tắc giấu tin trong bài

Quy tắc:
mv_x chẵn → bit 0.
mv_x lẻ → bit 1.
Kỹ thuật được gọi trong bài là MVX_LSB.

Bảng tùy chọn công cụ

Công cụ Tùy chọn / Cú pháp Mô tả tác dụng
curl http://evidence-server:8080/case/cctv.hevc Tải file chứng cứ từ máy chủ.
tcpdump -i eth0 -w transfer.pcap -Z root Bắt gói quá trình tải file.
ffprobe -show_entries stream=codec_name,width,height,r_frame_rate Kiểm tra thông tin luồng video.
strings | grep HEVC Tìm chuỗi ASCII dễ thấy trong video.
python3 tools/*.py Chạy tool quét NAL, dump motion vector và trích xuất thông điệp.

Nhiệm vụ 1 — Lấy chứng cứ từ evidence-server

Mục đích: lấy video nghi vấn từ máy chủ nội bộ. Đây là chứng cứ chính cần phân tích trong các task sau.

Tải file video từ máy chủ chứng cứ:

curl -v http://evidence-server:8080/case/cctv.hevc -o cctv.hevc > curl.stdout 2>&1
cat curl.stdout
ls -lh cctv.hevc

Trong curl.stdout, cần thấy kết nối tới evidence-server và phản hồi HTTP thành công. File tải về tên là cctv.hevc.

Điều kiện hoàn thành: File curl.stdout có chuỗi evidence-server.
Nhiệm vụ 2 — Kiểm tra video H.265

Mục đích: xác nhận file tải về là video H.265 thật, không phải file text hoặc dữ liệu giả.

Dùng file và ffprobe để kiểm tra video:

file cctv.hevc
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,r_frame_rate -of default=noprint_wrappers=1 cctv.hevc > ffprobe.stdout
cat ffprobe.stdout

Output cần có codec_name=hevc. Nếu không có dòng này, các bước phân tích bitstream phía sau không có ý nghĩa.

Điều kiện hoàn thành: File ffprobe.stdout có codec_name=hevc.
Nhiệm vụ 3 — Bắt gói quá trình tải file

Mục đích: lưu lại bằng chứng mạng cho thấy file video được tải từ evidence-server qua HTTP.

Cách dễ nhất là chạy tcpdump nền, sau đó tải lại file bằng curl:

sudo tcpdump -i eth0 -w transfer.pcap -Z root host evidence-server > tcpdump.stdout 2>&1 &

Sau đó tải lại video để tạo traffic HTTP:

curl http://evidence-server:8080/case/cctv.hevc -o cctv.hevc

Kiểm tra file pcap đã được tạo:

ls -lh transfer.pcap
cat tcpdump.stdout

Nếu chạy tcpdump ở foreground, dừng bằng Ctrl+C. Tùy chọn -Z root giúp tránh lỗi quyền ghi file trong container.

Điều kiện hoàn thành: File tcpdump.stdout có chuỗi tcpdump.
Nhiệm vụ 4 — Kiểm tra không có SEI dễ thấy

Mục đích: chứng minh video không dùng kiểu giấu tin dễ thấy qua SEI/ASCII như lab 1.

Thử tìm chuỗi rõ ràng trong video:

strings cctv.hevc | grep HEVC

Chạy tool tổng quan NAL:

python3 tools/nal_overview.py cctv.hevc > nal_overview.py.stdout
cat nal_overview.py.stdout

Kết quả SEI_SUSPICIOUS=NO nghĩa là không có dấu hiệu SEI rõ ràng. Vì vậy cần chuyển hướng sang phân tích motion vector.

Điều kiện hoàn thành: Output có SEI_SUSPICIOUS=NO.
Nhiệm vụ 5 — Xem mẫu motion vector

Mục đích: quan sát các mẫu mv_x được dùng làm carrier cho kênh giấu tin.

Dump các mẫu motion vector:

python3 tools/mv_dump.py cctv.hevc > mv_dump.py.stdout
cat mv_dump.py.stdout

Output gồm nhiều dòng dạng frame=... block=... mv_x=... mv_y=.... Quan sát tính chẵn/lẻ của cột mv_x. Cuối file cần có MV_RECORDS=200.

Điều kiện hoàn thành: Output có MV_RECORDS=200.
Nhiệm vụ 6 — Sửa extractor để khôi phục thông điệp

Mục đích: chuyển dãy parity của mv_x thành bit, rồi ghép 8 bit thành ký tự ASCII.

Mở file extractor:

nano tools/mv_extract.py

Trong file có hai phần cần sửa:

TODO Task 6.1: lấy bit từ tính chẵn/lẻ của mv_x. Vì mv_x có thể âm, nên dùng abs(). 
bit = abs(rec.mv_x) % 2
TODO Task 6.2: ghép bit vào byte theo thứ tự bit cao trước. 
value = (value << 1) | bit

Lưu file bằng Ctrl + O, Enter, thoát bằng Ctrl + X.

Chạy extractor:

python3 tools/mv_extract.py cctv.hevc > mv_extract.py.stdout
cat mv_extract.py.stdout
Điều kiện hoàn thành: Output có MV_MESSAGE=HEVC{motion_leak_in_cctv}.
Nhiệm vụ 7 — Đối chiếu log máy chủ

Mục đích: xác định user đã upload/export video nghi vấn.

Tải hoặc đọc log từ evidence-server:

curl http://evidence-server:8080/logs/cctv_export.log -o cctv_export.log
grep uploaded cctv_export.log > grep.stdout
cat grep.stdout

Dòng log cần tìm có user intern01. Đây là tài khoản đáng ngờ trong kịch bản.

Điều kiện hoàn thành: File grep.stdout có intern01.
Nhiệm vụ 8 — Viết kết luận điều tra

Mục đích: tổng hợp kết quả điều tra gồm user đáng ngờ, thông điệp khôi phục và kỹ thuật giấu tin.

Tạo file kết luận:

nano answer.txt

Nội dung cần ghi:

intern01 HEVC{motion_leak_in_cctv} MVX_LSB
Điều kiện hoàn thành: File answer.txt có đủ user, thông điệp và kỹ thuật.
