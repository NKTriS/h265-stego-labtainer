H.265 Stego — Phân tích giấu tin trong SEI và VCL slice
Mức độ: Trung bình Digital Forensics Video Steganography

1. Giới thiệu Lab

Thông tin Chi tiết
Tên Lab h265-stego
Mức độ Trung bình
Công cụ sử dụng ffprobe, xxd, strings, grep, python3, nano

Mục tiêu học tập

Bài lab giúp sinh viên thực hành quy trình phân tích một file H.265/HEVC nghi có dữ liệu ẩn. Sinh viên cần kiểm tra định dạng video, quan sát header Annex B, quét NAL unit, tìm dấu vết SEI, sửa một vài dòng Python để giải mã thông điệp trong SEI và tách thông điệp ở mức VCL slice.

Kỹ năng đạt được

  • Kiểm tra thông tin codec bằng ffprobe.
  • Quan sát byte đầu file bằng xxd.
  • Hiểu bố cục NAL unit trong H.265/HEVC.
  • Tìm chuỗi gợi ý trong SEI bằng strings và grep.
  • Sửa code Python nhỏ để giải mã dữ liệu ẩn.
  • Tạo các file báo cáo để Labtainer tự chấm bằng checkwork.

2. Kịch bản

Tình huống: Sinh viên nhận được một file evidence.hevc từ hệ thống giám sát. File này vẫn là video H.265 hợp lệ nhưng bị nghi có chứa dữ liệu ẩn.

Vấn đề: Dữ liệu ẩn không nằm ở một vị trí duy nhất. Một phần dấu vết nằm trong SEI dưới dạng metadata, phần còn lại nằm ở mức VCL slice. Sinh viên cần kết hợp lệnh Linux và sửa code nhỏ để khôi phục đầy đủ thông tin.

3. Kiến thức bổ trợ

Annex B và NAL unit

File H.265 dạng Annex B thường chứa các start code như 00 00 00 01 để đánh dấu điểm bắt đầu NAL unit. Mỗi NAL unit có kiểu riêng, ví dụ VPS, SPS, PPS, SEI hoặc VCL slice.

SEI và VCL slice

SEI thường chứa thông tin phụ trợ hoặc metadata. VCL slice chứa dữ liệu hình ảnh đã mã hóa. Trong bài này, sinh viên cần phân tích cả hai vùng để khôi phục thông điệp.

Bảng tùy chọn công cụ

Công cụ Tùy chọn / Cú pháp Mô tả tác dụng
imodule <URL tar.gz> Tải bài lab vào Labtainer.
ffprobe -show_entries stream=codec_name,width,height,r_frame_rate Kiểm tra thông tin luồng video.
xxd -l 96 Xem 96 byte đầu file để nhận diện header Annex B.
strings | grep HE265LAB Tìm chuỗi ASCII gợi ý trong file.
python3 tools/*.py Chạy các tool quét NAL, giải mã SEI và trích xuất VCL.

Nhiệm vụ 1 — Ghi thông tin codec

Mục đích: xác nhận file chứng cứ là luồng video H.265 thật, không phải file giả mạo đổi đuôi.

Trong nhiệm vụ này, evidence/evidence.hevc là video nghi vấn cần kiểm tra. Kết quả được lưu vào report/video_info.txt để làm ghi chép thông tin codec của ca điều tra.

Dùng ffprobe để lấy thông tin codec, kích thước và frame rate:

ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,r_frame_rate -of default=noprint_wrappers=1 evidence/evidence.hevc > report/video_info.txt
cat report/video_info.txt
Giải thích lệnh:
ffprobe đọc metadata của file video. -v error chỉ hiện lỗi, tránh output dài. -select_streams v:0 chọn luồng video đầu tiên. -show_entries chỉ lấy các trường cần xem. Dấu > ghi kết quả vào report/video_info.txt. Lệnh cat dùng để mở lại file kết quả trên terminal.

Khi xem file kết quả, cần chú ý dòng codec_name=hevc. Đây là dấu hiệu cho thấy file được giải mã như video H.265/HEVC.

Điều kiện hoàn thành: File report/video_info.txt có codec_name=hevc.
Nhiệm vụ 2 — Xem header Annex B bằng hex

Mục đích: nhận diện dạng Annex B của HEVC. Dạng này thường có start code 00 00 00 01 trước mỗi NAL unit.

File report/header_hex.txt lưu phần hex đầu file. Sinh viên dùng nó để nhìn trực tiếp start code thay vì chỉ tin vào kết quả của ffprobe.

Dùng xxd để xem 96 byte đầu file:

xxd -l 96 evidence/evidence.hevc > report/header_hex.txt
cat report/header_hex.txt
Giải thích lệnh:
xxd chuyển dữ liệu nhị phân sang dạng hex để đọc được bằng mắt. -l 96 nghĩa là chỉ lấy 96 byte đầu, đủ để thấy start code và header ban đầu. Kết quả được lưu vào report/header_hex.txt để sinh viên có bằng chứng về định dạng Annex B.

Dòng đầu cần bắt đầu bằng 00000000: 0000 0001. Nếu thấy giá trị này, sinh viên có thể hiểu file đang dùng start code Annex B.

Điều kiện hoàn thành: File report/header_hex.txt có 00000000: 0000 0001.
Nhiệm vụ 3 — Quét NAL unit

Mục đích: xem file có bao nhiêu NAL unit và phân biệt nhóm VCL, VPS, SPS, PPS, SEI.

Tool tools/nal_scan.py đọc bitstream HEVC, tách từng NAL unit và in bảng thống kê. Output report/nal_scan.txt giúp xác định trong file có SEI và VCL để tiếp tục điều tra.

Chạy tool quét bố cục NAL:

python3 tools/nal_scan.py evidence/evidence.hevc > report/nal_scan.txt
cat report/nal_scan.txt
Giải thích lệnh:
python3 tools/nal_scan.py chạy script quét NAL. Tham số evidence/evidence.hevc là file đầu vào. Output được chuyển vào report/nal_scan.txt để lưu bảng thống kê. Khi dùng cat, sinh viên sẽ thấy danh sách NAL và dòng tổng hợp cuối file.

Cuối output sẽ có dòng tổng hợp. Trong bài này dòng cần quan sát là NAL_SUMMARY=171:5:5:5:6:150, nghĩa là file có 171 NAL, trong đó có 150 NAL loại VCL.

Điều kiện hoàn thành: File report/nal_scan.txt có NAL_SUMMARY=171:5:5:5:6:150.
Nhiệm vụ 4 — Tìm dấu vết SEI dạng ASCII

Mục đích: kiểm tra xem trong file có chuỗi ASCII đáng ngờ hay không. Với dữ liệu giấu trong SEI, đôi khi UUID hoặc nhãn nhận diện vẫn có thể thấy bằng strings.

File report/sei_hint.txt chỉ là dấu vết ban đầu. Nó không phải thông điệp cuối, nhưng cho biết nên mở rộng phân tích vào SEI NAL.

Dùng strings kết hợp grep để tìm chuỗi gợi ý:

strings evidence/evidence.hevc | grep HE265LAB > report/sei_hint.txt
cat report/sei_hint.txt
Giải thích lệnh:
strings lấy các chuỗi ASCII có thể đọc được trong file nhị phân. Dấu | đưa output của strings sang grep. grep HE265LAB chỉ giữ các dòng có nhãn nghi vấn. File report/sei_hint.txt là bằng chứng ban đầu rằng có dữ liệu dạng SEI/metadata đáng kiểm tra.

Nếu thấy HE265LABSTEGO001, đó là dấu hiệu cho biết có SEI user data cần phân tích sâu hơn.

Điều kiện hoàn thành: File report/sei_hint.txt có HE265LABSTEGO001.
Nhiệm vụ 5 — Sửa tool giải mã SEI

Mục đích: tìm SEI NAL, lấy payload loại user_data_unregistered, sau đó thử XOR để tìm plaintext.

File tools/sei_probe.py là script cần sửa trong nhiệm vụ này. Script dùng helper tools/rbsp.py để xử lý dữ liệu NAL; sinh viên không cần sửa file helper. Kết quả giải mã được lưu vào report/sei_decode.txt.

Mở file tools/sei_probe.py và hoàn thành các dòng TODO:

nano tools/sei_probe.py
Giải thích file:
nano mở file để sửa trực tiếp trong terminal. Trong sei_probe.py, các dòng TODO đang cố tình để thiếu để sinh viên tự hoàn thiện logic: lọc đúng NAL loại SEI, chọn đúng payload type và giải XOR. Sau khi sửa, lưu bằng Ctrl + O, nhấn Enter, rồi thoát bằng Ctrl + X.

Cần sửa các phần sau:

TODO Task 5.1: chỉ xử lý SEI NAL type 39 hoặc 40.
Thay điều kiện if True: thành: 
if nal.nal_type not in (39, 40):
TODO Task 5.2: payload user_data_unregistered có payload_type == 5 và dài hơn 16 byte UUID.
Thay if False: thành: 
if payload_type == 5 and len(payload) >= 16:
TODO Task 5.3 và 5.4: thử XOR từng byte với khóa từ 0 đến 255, chọn plaintext bắt đầu bằng HEVC-LAB{. 
text = bytes(byte ^ key for byte in payload)
if text.startswith(b"HEVC-LAB{"):

Lưu file bằng Ctrl + O, Enter, thoát bằng Ctrl + X.

Sau khi sửa, chạy tool:

python3 tools/sei_probe.py evidence/evidence.hevc > report/sei_decode.txt
cat report/sei_decode.txt
Giải thích lệnh:
Script nhận evidence/evidence.hevc làm đầu vào, tự tìm SEI NAL và thử giải mã payload. File report/sei_decode.txt lưu thông điệp tìm được để sinh viên có thể đối chiếu lại sau. Nếu sửa code sai, file này thường rỗng hoặc không có dòng SEI_MESSAGE.
Điều kiện hoàn thành: Output có SEI_MESSAGE=HEVC-LAB{metadata_is_not_pixels}.
Nhiệm vụ 6 — Sửa tool tách thông điệp trong VCL slice

Mục đích: tách bit được giấu ở phần byte 0 cuối payload của các VCL NAL.

File tools/vcl_extract.py là extractor cho phần VCL slice. Khác với nhiệm vụ SEI, dữ liệu ở đây nằm trong NAL chứa dữ liệu hình ảnh đã mã hóa. Output cuối được ghi vào report/vcl_message.txt.

Mở file tools/vcl_extract.py và hoàn thành các dòng TODO:

nano tools/vcl_extract.py
Giải thích file:
vcl_extract.py xử lý các NAL chứa dữ liệu hình ảnh đã mã hóa. Bài lab không yêu cầu viết parser HEVC từ đầu; sinh viên chỉ sửa phần logic lấy bit: bỏ qua NAL không phải VCL, đếm byte 0x00 cuối payload, rồi ghép bit thành byte.

Cần sửa các phần sau:

TODO Task 6.1: chỉ lấy NAL loại VCL. Trong helper nal_scan.py, mỗi NAL có thuộc tính is_vcl. 
if not nal.is_vcl:
    continue
TODO Task 6.2: đếm số byte 0x00 ở cuối NAL payload. 
zero_count = len(nal.data) - len(nal.data.rstrip(b"\x00"))
TODO Task 6.3: ghép 8 bit thành 1 byte theo thứ tự bit cao trước. 
value = (value << 1) | bit

Lưu file, sau đó chạy tool:

python3 tools/vcl_extract.py evidence/evidence.hevc > report/vcl_message.txt
cat report/vcl_message.txt
Giải thích lệnh:
Lệnh chạy extractor trên video nghi vấn và lưu kết quả vào report/vcl_message.txt. File này là kết quả của kênh giấu tin thứ hai, khác với report/sei_decode.txt ở nhiệm vụ trước. Dùng cat để kiểm tra thông điệp sau khi script chạy xong.
Điều kiện hoàn thành: Output có SLICE_MESSAGE=SLICE:qpel_path.
